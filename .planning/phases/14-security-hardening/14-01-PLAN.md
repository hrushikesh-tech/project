<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client credentials -> Keycloak proxy auth layer | Login and refresh requests cross from untrusted clients into the backend token-exchange path |
| backend session registry -> Keycloak-issued tokens | The app must reconcile its own session ledger with an external identity provider |
| super-admin request context -> tenant-scoped business modules | Incorrect tenant switching could bypass tenant isolation across the whole ERP |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Elevation of Privilege | auth refresh/session path | mitigate | Add durable session tracking, one-time refresh-token use, and max-5 active-session enforcement |
| T-14-02 | Information Disclosure | super-admin tenant switching | mitigate | Keep explicit `x-tenant-id` switching and record the effective tenant in audit metadata |
| T-14-03 | Repudiation | audit trail | mitigate | Persist tenant-override intent and session identifiers so incident review can reconstruct who acted where |
</threat_model>
