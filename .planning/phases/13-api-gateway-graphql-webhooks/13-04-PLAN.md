<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GraphQL clients -> BI query engine | Arbitrary query structure can stress resolver paths or bypass intended BI access patterns |
| GraphQL context -> existing auth/tenant guards | HTTP-oriented auth assumptions must adapt safely to GraphQL execution context |
| production operators -> trusted manifest and env flags | Misconfigured policy could expose introspection or unrestricted query execution in production |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-10 | Information Disclosure | GraphQL introspection | mitigate | Disable introspection in production and keep the graph BI-only |
| T-13-11 | Denial of Service | GraphQL query execution | mitigate | Enforce trusted operations, depth limits, complexity limits, and request-scoped batching |
| T-13-12 | Elevation of Privilege | GraphQL auth bridge | mitigate | Reuse BI REST roles and tenant semantics through GraphQL-aware request extraction rather than creating looser resolver-local auth |
</threat_model>
