<threat_model>

## Trust Boundaries

| Boundary                                 | Description                                                                                       |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| successful CI on main -> deploy workflow | The deploy path must trust only verified main-branch state, not arbitrary PR code                 |
| deploy workflow -> repo write-back       | Bad promotion commits could create rollout loops or move the wrong tags into watched values files |
| staging artifact -> production artifact  | Rebuilding for prod would break same-artifact guarantees and weaken release auditability          |

## STRIDE Threat Register

| Threat ID | Category               | Component                    | Disposition | Mitigation Plan                                                                                 |
| --------- | ---------------------- | ---------------------------- | ----------- | ----------------------------------------------------------------------------------------------- |
| T-17-07   | Elevation of Privilege | deploy trigger path          | mitigate    | Trigger deploy only from successful trusted `main` CI runs and keep PR CI separate              |
| T-17-08   | Tampering              | promotion commits            | mitigate    | Use one checked-in values-update helper plus loop-prevention rules for machine-authored commits |
| T-17-09   | Repudiation            | production artifact identity | mitigate    | Carry one immutable tag family from trusted build to staging and production without rebuild     |

</threat_model>
