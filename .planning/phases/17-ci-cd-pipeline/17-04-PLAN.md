<threat_model>

## Trust Boundaries

| Boundary                                        | Description                                                                                                 |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| staging deployment -> production availability   | Production must not become reachable before staging proves the bounded live gate                            |
| live smoke specs -> release truth               | If the smoke path is too weak or accidentally local-only, the gate gives false confidence                   |
| workflow behavior -> operator rollback response | If docs and workflow diverge, operators may execute the wrong rollback or reproduction steps under pressure |

## STRIDE Threat Register

| Threat ID | Category               | Component              | Disposition | Mitigation Plan                                                                         |
| --------- | ---------------------- | ---------------------- | ----------- | --------------------------------------------------------------------------------------- |
| T-17-10   | Repudiation            | live smoke gate        | mitigate    | Add dedicated external-targeted API and browser smoke checks with explicit staging URLs |
| T-17-11   | Elevation of Privilege | production gate        | mitigate    | Keep production approval and prod values update downstream of staging smoke success     |
| T-17-12   | Tampering              | rollback understanding | mitigate    | Document truthful GitOps rollback behavior in the same repo that owns promotion         |

</threat_model>
