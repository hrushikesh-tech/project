<threat_model>

## Trust Boundaries

| Boundary                           | Description                                                                                           |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------- |
| PR workflow -> repository trust    | Over-permissioned CI on untrusted PR code could expose deploy or write-back capabilities              |
| scanner jobs -> release confidence | Advisory-only or misconfigured scanners could allow secrets or HIGH/CRITICAL risk through the PR gate |
| local commands -> workflow truth   | If CI uses hidden commands not reproducible locally, failures will be harder to debug and audit       |

## STRIDE Threat Register

| Threat ID | Category               | Component               | Disposition | Mitigation Plan                                                                  |
| --------- | ---------------------- | ----------------------- | ----------- | -------------------------------------------------------------------------------- |
| T-17-04   | Elevation of Privilege | PR workflow permissions | mitigate    | Keep CI permissions minimal and isolate deploy secrets from PR validation        |
| T-17-05   | Information Disclosure | secrets scan gate       | mitigate    | Reuse the checked-in trufflehog implementation as a hard blocker                 |
| T-17-06   | Repudiation            | vulnerability gates     | mitigate    | Enforce Snyk and Trivy fail-on-HIGH/CRITICAL with checked-in reviewed exceptions |

</threat_model>
