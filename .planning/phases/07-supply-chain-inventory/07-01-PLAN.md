# Plan 07-01: Supply-Chain Schema Foundations, Shared Contracts, and Test Harness

<objective>
Create the Phase 7 domain foundation required by every downstream task: warehouse-targeted goods receipts, explicit replenishment configuration for reorder automation, auditable inventory movements, shared supply-chain exceptions/contracts, and a dedicated supply-chain test harness. Finish with the blocking Prisma sync before any module or queue implementation begins.
</objective>

<must_haves>

- Goods receipts can target one explicit warehouse
- Reorder automation has explicit vendor, legal-entity, and quantity sourcing data instead of heuristics
- Inventory receipts and stock issues can be recorded durably for FIFO and audit purposes
- Shared supply-chain exceptions/contracts are exported through `@amdox/types`
- A dedicated supply-chain harness can seed vendors, products, warehouses, replenishment config, PO data, receipts, cost layers, and inventory movements
- Existing AP/AR harness support remains compatible with the evolved goods-receipt schema
- Prisma schema is pushed and regenerated before downstream supply-chain implementation
  </must_haves>

2. Extend `PurchaseOrder` with the lifecycle metadata needed for strict transition handling, such as:

5. Add the tenant, warehouse, product, and sourcing indexes needed for the new models.
6. Keep new workflow-state fields string-backed in application code rather than adding new Prisma enums, consistent with the Phase 2 hybrid-enum decision.

## Threat Model

<threat_model>

- **T-07-01: Warehouse-less receipt posting** - Without an explicit receipt warehouse, inventory updates and FIFO cost layers will be ambiguous or incorrect.
- **T-07-02: Heuristic reorder sourcing** - Without a replenishment config model, auto-reorder will guess vendor or legal entity and violate locked Phase 7 decisions.
- **T-07-03: FIFO without audit trail** - Without an inventory-movement log, stock consumption and receipt history will be hard to verify and debug.
- **T-07-04: Harness regression spillover** - If the evolved receipt schema is not reflected in the test harnesses, Phase 4 AP/AR verification can fail for harness reasons instead of product behavior.
  </threat_model>
