# Plan 07-03: Goods Receipts, FIFO Inventory Consumption, and 6-Hour Reorder Automation

<objective>
Implement the Phase 7 operational core: warehouse-targeted goods receipts, FIFO inventory updates and depletion, an explicit stock-consumption path that throws `InsufficientStockException`, and tenant-safe reorder automation that runs every 6 hours without guessing sourcing data.
</objective>

<must_haves>

- Goods receipt posting updates PO line received quantities, warehouse inventory, and FIFO layers atomically
- PO status advances to `PARTIALLY_RECEIVED` or `FULLY_RECEIVED` from receipt outcomes
- Inventory consumption depletes oldest cost layers first within the same product and warehouse
- Stock issue fails before partial depletion when insufficient inventory exists
- Reorder automation runs every 6 hours with explicit tenant payloads
- Reorder automation uses tenant-wide available stock, suppresses duplicate open POs, and never guesses vendor or legal entity
- Operator-visible skip reasons are persisted durably for missing config or blocked vendors
  </must_haves>

2. Receipt creation must require:
   - `purchaseOrderId`

## Threat Model

<threat_model>

- **T-07-09: Receipt/inventory split-brain** - If goods receipts do not update PO, inventory, and cost layers atomically, purchasing and stock views will drift.
- **T-07-10: Partial FIFO mutation on failure** - If stock validation happens after cost-layer mutation starts, inventory corruption can occur on insufficient stock.
- **T-07-11: Duplicate reorder drafts** - If open-PO suppression is incomplete, the 6-hour worker can create duplicate draft POs for the same shortage.
- **T-07-12: Silent reorder skips** - If missing config or blocked vendors are not recorded durably, operators will not know why replenishment failed to occur.
  </threat_model>
