# Plan 06-03: Payroll Saga, Payslip Generation, Summarized GL Posting, and Failure Compensation

<objective>
Implement the queue-backed execution path for payroll: BullMQ saga orchestration, employee-batch processing, payslip PDF generation and S3 storage, summarized GL posting through the finance layer, and the failure-compensation path that reverses partial accounting and alerts operators.
</objective>

<must_haves>

- Payroll uses BullMQ with explicit tenant payloads and batches of 100 employees
- Queue processing persists employee results before artifact or accounting steps
- Payslips are rendered through a dedicated PDF service and stored in S3
- Payroll accounting posts one summarized GL result per payroll run rather than one journal per employee
- Failure after GL posting triggers compensation using the finance reversal path
- Payroll success/failure emits durable admin-facing events or notifications in Phase 6
  </must_haves>

## Threat Model

<threat_model>

- **T-06-09: Queue-stage duplication** - Without explicit stage state and result persistence, retries can recalculate employees, regenerate artifacts, or double-post payroll.
- **T-06-10: Direct-journal bypass** - If payroll writes journals directly instead of reusing the finance path, balancing, period checks, and reversal guarantees can drift.
- **T-06-11: Artifact/GL ordering bug** - If payslip generation and GL posting order is unclear, failures can leave inconsistent payroll state without a safe compensation boundary.
- **T-06-12: Invisible payroll failure** - If failed runs do not emit durable admin-facing records, operators cannot inspect or recover Phase 6 payroll issues.
  </threat_model>
