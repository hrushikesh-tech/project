# Plan 06-02: Payroll Module, Persistent Compensation Management, and India Gross-to-Net Engine

<objective>
Implement the payroll runtime slice for compensation management and deterministic gross-to-net calculation: scaffold the NestJS payroll module, expose tenant-safe compensation and payroll-run APIs, and build the India payroll engine that supports both tax regimes, PF, professional tax, payable-days adjustments, and the five required salary scenarios.
</objective>

<must_haves>

- `apps/api/src/payroll` exists as a vertical module wired into `AppModule`
- Payroll APIs operate on persistent salary structures rather than ad hoc run payloads
- Gross-to-net calculation supports both India old and new regimes per employee
- Payroll inputs consume Phase 5 attendance/overtime and leave-derived payable-days/loss-of-pay data
- Calculation output produces immutable payroll-result-ready earnings, deductions, tax, and net-pay snapshots
- Unit coverage proves the five roadmap salary scenarios and tax-rule edge cases
  </must_haves>

## Threat Model

<threat_model>

- **T-06-05: Tax-calculation divergence** - Separate or incomplete handling of India regimes, rebate rules, PF, and professional tax can create incorrect net pay and compliance defects.
- **T-06-06: Hidden recomputation** - If payroll inputs are not snapshotted before orchestration, retries can re-read changed HR or compensation data and mutate historical payroll outcomes.
- **T-06-07: Illegal run overlap** - Multiple runs for the same legal entity + period can create duplicate payroll artifacts and conflicting GL intent.
- **T-06-08: Minor-unit drift** - If the engine uses float-style calculations or inconsistent rounding, payroll totals will no longer reconcile with the finance layer.
  </threat_model>
