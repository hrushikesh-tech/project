# Plan 08-01: Forecasting Schema, Shared Contracts, and Test Foundation

<objective>
Create the Phase 8 foundation required by every downstream forecasting task: durable forecast metadata, shared ML-domain exceptions and contracts, environment/config surface for the new service boundary, and a reusable API-side forecast harness. Finish with the Prisma sync before any runtime or orchestration work begins.
</objective>

<must_haves>

- Forecast models can represent training windows, artifact location, data-point counts, and promotion-ready metadata
- Forecast predictions can be linked back to the model version that generated them
- Shared ML-domain contracts and exceptions exist in `@amdox/types`
- Forecasting environment variables and thresholds are explicit in `.env.example`
- A reusable API-side forecast harness exists for demand-history, model, and prediction tests
- Prisma/client sync happens before downstream implementation

</must_haves>

## Threat Model

<threat_model>

- **T-08-01: Underspecified forecast registry** - Without richer model metadata and provenance, promotion and prediction behavior can become ambiguous and impossible to audit.
- **T-08-02: Quality gate encoded only in prose** - Without shared contracts and explicit env/config surface, the 20% MAPE gate can drift across runtimes.
- **T-08-03: Harness gap** - Without a reusable forecast harness, later Node tests will either under-test tenant/promotion behavior or duplicate brittle setup logic.

</threat_model>
