# Plan 02-01: Prisma Schema, Tenant Middleware & Soft Delete

<objective>
Define the complete Prisma schema with 40+ models in packages/db, implement tenant isolation via Prisma Client Extensions, soft-delete extension, and configure TimescaleDB hypertables for AuditLog and ForecastPrediction tables. This plan establishes the entire data layer foundation.
</objective>

<must_haves>
- All 40+ Prisma models defined with id, createdAt, updatedAt, deletedAt, tenantId
- Every tenantId and FK column indexed; composite indexes on (tenantId, status)
- TimescaleDB hypertables on AuditLog(timestamp) and ForecastPrediction(forecastDate)
- Prisma Client Extension auto-injects tenantId into every query
- Tenant extension throws error when tenantId is missing (non-SuperAdmin)
- SuperAdmin wildcard tenantId = * bypasses tenant filtering
- Soft-delete extension converts delete → update(deletedAt) and filters reads
</must_haves>

## Threat Model

<threat_model>
- **SQL Injection via raw queries:** Prisma parameterizes all queries. Raw SQL must use `$queryRaw` with template literals (parameterized). Never concatenate user input.
- **Tenant data leakage:** Extension rejects queries without tenantId. SuperAdmin wildcard is explicitly logged via AuditInterceptor.
- **Soft delete bypass:** Extension covers all Prisma operations. Direct SQL access must be restricted to DB admins only.
- **Schema exposure:** Prisma Studio must be disabled in production. Only accessible in development.
</threat_model>
