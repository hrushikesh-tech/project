# Plan 02-02: Keycloak Realm Configuration & Docker Infrastructure

<objective>
Configure Keycloak 25 with a complete realm export (7 roles, 2 OIDC clients, MFA policies, password policies, brute-force detection, and tenant_id protocol mapper). Update Docker Compose to auto-import the realm and use a separate keycloak_db database.
</objective>

<must_haves>
- Keycloak realm "amdox-erp" with all 7 roles defined
- OIDC clients: amdox-web (public, PKCE) and amdox-api (confidential)
- Password policy: 12+ chars, uppercase, lowercase, digits, special chars
- Brute force: lock after 5 failures for 30 minutes
- MFA required for super_admin and tenant_admin (TOTP, 6 digits, 30s)
- Protocol mapper injects tenant_id into JWT
- Separate keycloak_db database on TimescaleDB instance
- Docker Compose auto-imports realm on startup
</must_haves>

   ```sql
   -- Create separate database for Keycloak
   -- This runs automatically on first TimescaleDB startup
   CREATE DATABASE keycloak_db;
   ```
2. Update `docker-compose.yml` to mount the init script:
   ```yaml
   timescaledb:
     image: timescale/timescaledb:latest-pg17
     environment:
       POSTGRES_USER: root
       POSTGRES_PASSWORD: rootpassword
       POSTGRES_DB: amdox_erp
     ports:
       - "5432:5432"
     volumes:
       - pgdata:/var/lib/postgresql/data
       - ./infra/db/init.sql:/docker-entrypoint-initdb.d/init.sql
     healthcheck:
       test: ["CMD-SHELL", "pg_isready -U root -d amdox_erp"]
       interval: 10s
       timeout: 5s
       retries: 5
   ```
   Also add a named volume at the bottom:
   ```yaml
   volumes:
     pgdata:
   ```
</action>

<action>
Update the `keycloak` service in `docker-compose.yml`:

```yaml
keycloak:
  image: quay.io/keycloak/keycloak:25.0
  command: start-dev --import-realm
  environment:
    KC_DB: postgres
    KC_DB_URL: jdbc:postgresql://timescaledb:5432/keycloak_db
    KC_DB_USERNAME: root
    KC_DB_PASSWORD: rootpassword
    KC_BOOTSTRAP_ADMIN_USERNAME: admin
    KC_BOOTSTRAP_ADMIN_PASSWORD: adminpassword
  volumes:
    - ./infra/keycloak/amdox-realm.json:/opt/keycloak/data/import/amdox-realm.json:ro
  ports:
    - "8080:8080"
  depends_on:
    timescaledb:
      condition: service_healthy
  healthcheck:
    test: ["CMD-SHELL", "exec 3<>/dev/tcp/localhost/8080; echo -e \"GET /health/ready HTTP/1.1\\r\\nHost: localhost\\r\\nConnection: close\\r\\n\\r\\n\" >&3; grep -q '200 OK' <&3"]
    interval: 30s
    timeout: 10s
    retries: 5
```

Key changes:
- `command: start-dev --import-realm` (adds import flag)
- `KC_DB_URL` points to `keycloak_db` (not `amdox_erp`)
- Volume mount for realm JSON into `/opt/keycloak/data/import/`

Also update `.env.example` to add `KEYCLOAK_REALM="amdox-erp"` if not already present.
</action>

## Threat Model

<threat_model>
- **Realm secret in version control:** The amdox-api client secret (`amdox-api-dev-secret`) is a development-only value. Production secrets are managed via Keycloak Admin API or secrets manager. .env.example documents this.
- **Brute force:** Keycloak locks accounts after 5 failures for 30 minutes (AUTH-04).
- **Password policy:** 12+ chars with complexity requirements enforced at Keycloak level (AUTH-03).
- **MFA bypass:** TOTP is configured for super_admin/tenant_admin. The conditional OTP flow ensures it cannot be skipped.
</threat_model>
