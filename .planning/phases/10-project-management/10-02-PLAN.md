# Plan 10-02: Project Module, CRUD APIs, and Audit-Safe Tenant Surface

<objective>
Create the project-management NestJS module and implement tenant-safe CRUD endpoints for projects, tasks, and milestones with employee-backed manager validation, role gates, serialization, and audit integration.
</objective>

<must_haves>

- a dedicated `apps/api/src/project-management` vertical slice exists
- project, task, and milestone CRUD follow the repo's DTO + service + exception-filter pattern
- writes are restricted to `project_manager` and `tenant_admin`
- reads are available to `viewer` and role owners
- project mutations participate cleanly in the existing audit pipeline
- project manager assignment validates against `Employee`

</must_haves>

## Threat Model

<threat_model>

- **T-10-04: Access drift** - If project routes do not follow the repo's explicit `@Roles` pattern, writes can leak beyond the intended `project_manager` and `tenant_admin` audience.
- **T-10-05: Audit blind spot** - If project entities are not mapped into the audit interceptor lookup path, updates will lose before-state fidelity compared with other modules.
- **T-10-06: Cross-project linkage bug** - If milestone linkage is not project-validated, task data can silently connect across project boundaries.

</threat_model>
