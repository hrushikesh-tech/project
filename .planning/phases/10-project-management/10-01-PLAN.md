# Plan 10-01: Project Schema Foundations, Shared Contracts, and Test Harness

<objective>
Evolve the existing project-management schema into a usable domain foundation: tie projects to employee managers, link tasks directly to milestones, add project-domain exceptions/contracts, update the affected test helpers, and finish with the blocking Prisma/client sync before API implementation begins.
</objective>

<must_haves>

- `Project.managerId` becomes a real `Employee` relation
- tasks can link directly to milestones without a join table
- project-domain exceptions and shared exports exist in `@amdox/types`
- a reusable project-management harness exists before service/controller work starts
- the BI harness is updated so the manager relation change does not break shared project coverage
- Prisma/client state is synchronized before downstream plans proceed

</must_haves>

<action>
Update `packages/db/prisma/schema.prisma` with the exact structural changes below:

1. Change `Project.managerId` from a loose string into a real relation to `Employee`.
2. Add the reverse relation on `Employee` so managed projects are queryable from HR-backed ownership.
3. Add `Task.milestoneId` as the direct milestone linkage chosen in context, with a nullable relation to `ProjectMilestone`.
4. Add the reverse relation on `ProjectMilestone` for linked tasks.
5. Preserve the existing `TaskDependency` edge table and add any needed indexes to keep project-scoped task, milestone, and dependency lookups efficient.
6. Do not introduce a task-to-milestone join table and do not move project cost into a derived labor-cost model.

</action>

## Threat Model

<threat_model>

- **T-10-01: Ownership drift** - If project managers remain loose strings, utilization and alert recipients will drift away from HR-backed employee identity.
- **T-10-02: Linkage ambiguity** - If milestone linkage is not encoded directly in schema, execution can drift into a join-table design that contradicts the locked context.
- **T-10-03: Harness regression** - If shared test helpers stay user-backed while runtime becomes employee-backed, unrelated BI and project tests will fail for harness reasons instead of product reasons.

</threat_model>
