# Plan 10-04: Budget Overrun Alerting, Durable Events, and Regression Verification

<objective>
Complete Phase 10 by adding budget-overrun alerting with durable notification/outbox behavior, plus the integration and regression verification needed to prove the project module stays aligned with shared BI contracts.
</objective>

<must_haves>

- budget overrun detection fires at the locked `>= 10%` threshold
- alerts go to the project manager and tenant admins
- overrun alerts fire once per threshold crossing rather than on every edit while over budget
- durable `OutboxEvent` and `Notification` records are written for the alert
- integration coverage proves threshold-crossing behavior and suppresses duplicate alerts while still over threshold
- BI regression coverage confirms shared `Project` reads still work after the manager relation change

</must_haves>

<action>
Implement budget-overrun alerting with the exact behavior below:

1. Add `project-budget-alert.service.ts` or equivalent focused helper.
2. Evaluate the threshold on project create/update using the previous and next `actualCost` values.
3. Treat the threshold as crossed when `actualCost >= budget * 1.10`.
4. Emit alerts only when the project moves from below threshold to at-or-above threshold.
5. Create one `OutboxEvent` with a concrete event type such as `project.budget.overrun`.
6. Create in-app `Notification` records for all tenant admins and for the assigned project manager when that employee has a linked `userId`.
7. Do not re-emit alerts on later updates if the project remains above threshold without crossing back below first.

</action>

## Threat Model

<threat_model>

- **T-10-10: Alert spam** - If overrun detection does not compare previous and next threshold state, every project cost edit above threshold will emit duplicate alerts.
- **T-10-11: Recipient loss** - If manager and tenant-admin recipient resolution is not explicit, the alert can become durable but not actionable.
- **T-10-12: Cross-phase regression** - If BI project metrics break after Phase 10 changes, the project module will silently damage previously completed dashboard functionality.

</threat_model>

- Run `pnpm --filter @amdox/api build`.
- Run `pnpm --filter @amdox/api run test:unit:raw`.
- Run `pnpm --filter @amdox/api run test:integration:raw`.

</success_criteria>
