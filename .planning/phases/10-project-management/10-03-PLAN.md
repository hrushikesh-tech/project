# Plan 10-03: Dependency DAG Validation, Milestone Derivation, and Utilization Reporting

<objective>
Implement the derived project-management behavior that makes Phase 10 valuable: full-graph dependency validation, milestone status recomputation from linked tasks, and planning-oriented resource-utilization reporting.
</objective>

<must_haves>

- dependency creation and updates are limited to same-project tasks
- any cycle in the task graph throws `CircularDependencyException`
- milestone completion is derived from linked task state, not manual toggles
- utilization reporting returns `allocatedHours` and `availableHours` using the locked planning-oriented semantics
- unit tests cover graph validation, milestone recomputation, and utilization math

</must_haves>

<task id="10-03-02" priority="high">
<description>Recompute milestone status from linked task state whenever linked tasks change</description>
<read_first>
- packages/types/src/enums.ts
- .planning/phases/10-project-management/10-CONTEXT.md
- apps/api/src/project-management/project-management.service.ts
</read_first>
<action>
Implement milestone status derivation with the exact rules below:

1. Recompute the affected milestone when a linked task is created, updated, re-linked, unlinked, or moved to `DONE`.
2. Treat `DONE` as the only task-complete state for milestone completion.
3. Mark the milestone `COMPLETED` only when every linked task is `DONE`.
4. Keep the milestone non-complete when any linked task is not `DONE`.
5. Do not rely on a manual "complete milestone" endpoint to satisfy PM-05.

</action>
<acceptance_criteria>

- `project-management.service.ts` contains milestone recomputation logic
- File contains `DONE`
- File contains `COMPLETED`
- Milestone status is derived from linked tasks rather than a manual-only controller path

</acceptance_criteria>
</task>

## Threat Model

<threat_model>

- **T-10-07: Shallow cycle detection** - If validation only checks direct edges, longer cycles will pass and break execution ordering.
- **T-10-08: False milestone completion** - If milestone status ignores one remaining open task, dashboards and reports will show incorrect completion.
- **T-10-09: Capacity inflation** - If available hours ignore approved leave or inactive employees, utilization will understate staffing risk.

</threat_model>
