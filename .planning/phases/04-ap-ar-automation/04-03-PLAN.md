# Plan 04-03: Three-Way Matching, GL Auto-Posting, Review Events & Aging Reports

<objective>
Turn extracted invoices into operational AP/AR outcomes: run the three-way match engine for payable invoices, auto-post only matched AP invoices to the ledger, flag mismatches for AP review with durable notification records, keep AR invoices review-first, and expose unified AP/AR aging reports with bucket totals and detail rows.
</objective>

<must_haves>
- Three-way match enforces PO match, quantity coverage, amount variance within `1%`, and line similarity `>= 0.85`
- Fully matched payable invoices auto-approve and auto-post to GL
- Receivable invoices do not auto-post in Phase 4
- Failed matches remain reviewable and generate durable AP-team notification records
- Aging report uses one unified endpoint with `type=PAYABLE|RECEIVABLE`, summary totals, and drill-down rows
- Integration coverage proves upload-to-posting and mismatch-to-aging flows work end to end
</must_haves>

## Threat Model

<threat_model>
- **False-positive auto-posting:** Only post when PO reference, quantity coverage, amount variance, and similarity checks all pass.
- **Wrong-account posting:** Use explicit vendor/customer control accounts and legal-entity scoping; never infer accounts from request input alone.
- **Dropped mismatch alerts:** Persist outbox and optional notification rows in the same database boundary as invoice review-state changes.
- **Aging leakage across tenants:** Aging queries must remain tenant-scoped and legal-entity-filtered, even in report endpoints and background-triggered review flows.
</threat_model>
