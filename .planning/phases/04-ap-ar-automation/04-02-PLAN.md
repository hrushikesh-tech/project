# Plan 04-02: Invoice Upload, S3 Storage, BullMQ OCR Queue & Extraction Worker

<objective>
Implement the asynchronous invoice ingestion pipeline: secure multipart upload, S3 document persistence, BullMQ OCR job dispatch, Textract/Tesseract provider fallback, and OCR normalization into draft invoice records plus invoice lines.
</objective>

<must_haves>
- Upload endpoint validates MIME type, magic bytes, and `10MB` file size limit
- Source invoice document is written to S3 before OCR begins
- Upload creates a draft invoice and queues an OCR job in BullMQ
- OCR worker supports `Textract` primary with `Tesseract` fallback
- OCR output populates invoice metadata, invoice lines, totals, and tax
- Failures stay reviewable instead of losing the document or orphaning the invoice
- Partial OCR outcomes remain reviewable draft invoices rather than rejected imports
</must_haves>

## Threat Model

<threat_model>
- **Malicious file uploads:** Validate MIME type, magic bytes, and size before storage or OCR.
- **Worker replay / duplicate processing:** Processor must short-circuit already-completed invoices and use explicit OCR status transitions.
- **Credential leakage:** S3/Textract access must come from env vars only; never hardcode credentials in providers or tests.
- **Inline request exhaustion:** OCR must stay async in BullMQ so API latency stays bounded and uploads cannot tie up request threads.
</threat_model>
