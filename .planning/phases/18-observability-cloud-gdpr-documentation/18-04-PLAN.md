<threat_model>

## Trust Boundaries

| Boundary                                    | Description                                                                                               |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| DSR request -> background jobs              | Incorrect workflow design could lose auditability or miss the 72-hour SLA                                 |
| PII records -> erasure logic                | Over-broad deletion could damage regulated history; under-broad erasure could violate privacy obligations |
| export artifacts -> object storage delivery | Unsigned or long-lived artifact access could expose personal data improperly                              |

## STRIDE Threat Register

| Threat ID | Category               | Component        | Disposition | Mitigation Plan                                                                                              |
| --------- | ---------------------- | ---------------- | ----------- | ------------------------------------------------------------------------------------------------------------ |
| T-18-10   | Repudiation            | DSR jobs         | mitigate    | Make DSR export and erasure workflows explicit, asynchronous, and traceable through a first-class GDPR slice |
| T-18-11   | Tampering              | erasure handling | mitigate    | Enforce pseudonymisation and retention by data class instead of blanket deletion                             |
| T-18-12   | Information Disclosure | export artifacts | mitigate    | Use encrypted exports plus signed download semantics and explicit artifact expiry                            |

</threat_model>
