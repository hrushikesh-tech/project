## Trust Boundaries

| Boundary                             | Description                                                                                                                   |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------- |
| repo Terraform -> AWS account        | Mis-scoped infrastructure code could provision the wrong environment or unsafe cloud posture                                  |
| Terraform outputs -> app-tier config | Missing or incorrect glue could break the existing Helm/ArgoCD deployment contract                                            |
| infrastructure docs -> operators     | Ambiguous ownership could cause operators to use Terraform for app rollout or GitOps for managed-service concerns incorrectly |

## STRIDE Threat Register

| Threat ID | Category               | Component                    | Disposition | Mitigation Plan                                                                                          |
| --------- | ---------------------- | ---------------------------- | ----------- | -------------------------------------------------------------------------------------------------------- |
| T-18-07   | Tampering              | Terraform ownership boundary | mitigate    | Keep a clear root/module structure and explicit README ownership split with Helm and ArgoCD              |
| T-18-08   | Elevation of Privilege | IAM and service-account glue | mitigate    | Scope IAM/service-account wiring explicitly as platform glue and validate it through Terraform artifacts |
| T-18-09   | Denial of Service      | managed-service contract     | mitigate    | Validate Terraform structure and environment overlays before dependent app or GDPR work assumes them     |

</threat_model>
