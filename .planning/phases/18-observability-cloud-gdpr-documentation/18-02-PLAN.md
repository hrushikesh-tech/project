## Trust Boundaries

| Boundary                        | Description                                                                                 |
| ------------------------------- | ------------------------------------------------------------------------------------------- |
| telemetry metrics -> dashboards | Bad dashboard queries could hide real application failures or misrepresent business signals |
| metrics and rules -> alerting   | Incorrect alert thresholds could create noisy or missing incident detection                 |
| operator docs -> repo assets    | Drift between docs and monitoring assets would make the observability surface untrustworthy |

## STRIDE Threat Register

| Threat ID | Category          | Component         | Disposition | Mitigation Plan                                                                                |
| --------- | ----------------- | ----------------- | ----------- | ---------------------------------------------------------------------------------------------- |
| T-18-04   | Repudiation       | dashboards        | mitigate    | Keep repo-owned dashboard definitions in git and align them directly to emitted metric names   |
| T-18-05   | Denial of Service | alerting          | mitigate    | Use bounded high-signal alert thresholds that match the roadmap and avoid platform-wide sprawl |
| T-18-06   | Tampering         | operator guidance | mitigate    | Validate README guidance against the actual observability assets and Helm dependency contract  |

</threat_model>
