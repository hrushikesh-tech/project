<threat_model>

## Trust Boundaries

| Boundary                                  | Description                                                                                        |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------- |
| runtime bootstrap -> telemetry exporters  | Bad bootstrap order or missing guards could crash application processes or silently drop telemetry |
| application seams -> business metrics     | Incorrect metric sourcing could create false operational confidence or misleading alerts           |
| env and Helm config -> telemetry backends | Hardcoded or mismatched endpoints could leak data or break staging/prod observability consistency  |

## STRIDE Threat Register

| Threat ID | Category               | Component         | Disposition | Mitigation Plan                                                                                           |
| --------- | ---------------------- | ----------------- | ----------- | --------------------------------------------------------------------------------------------------------- |
| T-18-01   | Denial of Service      | runtime bootstrap | mitigate    | Keep telemetry initialization explicit, bounded, and tested across API, worker, and ML entrypoints        |
| T-18-02   | Tampering              | business metrics  | mitigate    | Source metrics from real runtime seams with stable naming and reviewable instrumentation points           |
| T-18-03   | Information Disclosure | telemetry config  | mitigate    | Keep endpoints and config env-driven through `.env.example` and Helm values rather than hardcoded secrets |

</threat_model>
