# Plan 09-04: Scheduled Reports, Artifact Delivery, and Phase Verification

<objective>
Implement scheduled BI reporting end to end: queue-backed report scheduling, dashboard snapshot rendering to PDF and Excel, S3-backed artifact persistence, emailed download links, durable operator-visible failure state, and the final Phase 9 validation updates.
</objective>

<must_haves>

- Saved dashboards can be scheduled for queued report generation
- Each report run produces PDF and Excel outputs from the same snapshot
- Artifacts are stored durably and emailed as download links
- Failures persist operator-visible status and reasons
- Integration coverage proves the report path end to end
- The validation artifact is updated with the real Phase 9 verification contract

</must_haves>

## Threat Model

<threat_model>

- **T-09-10: Silent report loss** - If report failures are not persisted durably, operators will not know that scheduled BI delivery is broken.
- **T-09-11: Snapshot inconsistency** - If PDF and Excel are generated from different live reads, scheduled reports can disagree with themselves.
- **T-09-12: Delivery overreach** - If the implementation uses file attachments instead of links, scheduled reporting will become heavier and harder to scale operationally.

</threat_model>
