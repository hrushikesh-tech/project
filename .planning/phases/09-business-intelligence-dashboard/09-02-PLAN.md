# Plan 09-02: BI Module, Dashboard CRUD, Widget Contracts, and Metric Read Surface

<objective>
Implement the request-path BI backend slice: scaffold the NestJS BI module, expose tenant-safe dashboard CRUD and widget management, and create the fixed metric read contracts that downstream aggregation and SSE work will use.
</objective>

<must_haves>

- `apps/api/src/bi` exists as a vertical module wired into `AppModule`
- Dashboard CRUD enforces tenant scope, owner rules, and tenant-admin override behavior
- Widget APIs persist only supported widget types and fixed metric keys
- Metric read endpoints use explicit validated DTOs rather than a generic query contract
- Integration coverage proves dashboard and widget behavior through the API surface

</must_haves>

<action>
Implement the BI service-layer behavior for dashboard and widget management with these exact guarantees:

1. Dashboard CRUD:
   - create/list/get/update/delete dashboards
   - dashboards remain tenant-scoped
   - owners may manage their own dashboards
   - `tenant_admin` may manage any tenant dashboard
2. Visibility:
   - `isPublic` means tenant-internal read-only visibility only
   - no anonymous or cross-tenant reads are allowed
3. Widget management:
   - upsert/remove widgets within a dashboard
   - persist title, type, metric key, layout/position, refresh participation, and constrained config JSON
   - reject unsupported widget types or unsupported metric keys
4. Keep widget config constrained to the locked BI contract instead of permitting arbitrary analytics-builder behavior.

Do not implement per-widget ACLs or cross-dashboard widget reuse in Phase 9.
</action>

## Threat Model

<threat_model>

- **T-09-04: Generic analytics drift** - If metric routes accept arbitrary filters or grouping, BI will become an unsafe open query surface.
- **T-09-05: Dashboard access leakage** - If owner and tenant-public rules are underspecified, dashboards can leak across tenants or roles.
- **T-09-06: Invalid widget persistence** - If unsupported metric/widget combinations are saved, later aggregation and reporting code will fail unpredictably.

</threat_model>
