# Plan 16-02: Helm Chart And Environment Overlays

<objective>
Create the Phase 16 Helm chart for the application tier, including values overlays, external dependency wiring, app-tier Deployments and Services, and the quota/policy resources required by the roadmap.
</objective>

<must_haves>

- one application chart exists under `infra/helm/amdox`
- base values plus `dev`, `staging`, and `prod` overlays exist
- the chart deploys `web`, `api`, `api-worker`, and `ml-service`
- external dependencies are modeled through values and Secret references, not subcharts
- HPA, PDB, NetworkPolicy, ResourceQuota, and LimitRange resources are included in the chart

</must_haves>

## Threat Model

<threat_model>

- **T-16-04: Secret material committed through values drift** - If chart values contain live credentials instead of Secret references, the phase violates the locked security posture immediately.
- **T-16-05: Over-broad network egress** - If NetworkPolicy is omitted or too loose, app workloads can talk to unintended destinations and weaken tenant/security boundaries.
- **T-16-06: Workload contract mismatch** - If the chart does not distinguish `api` from `api-worker`, Kubernetes scaling will not reflect the intended runtime split.

</threat_model>
