# Plan 05-01: HR Schema, Shared Contracts, Blocking Prisma Sync, and Test Harness

<objective>
Harden the existing HR data model and shared contracts so employee lifecycle, department hierarchy, leave workflow, and attendance logic can be implemented safely on top of tenant-aware records. Establish the HR test harness and perform the mandatory Prisma push/generate step before downstream module work begins.
</objective>

<must_haves>

- Employee lifecycle supports pre-start records, effective-date terminations, and roster-safe querying
- Department heads are modeled as explicit employee relations with same-department validation support
- Leave requests carry enough audit metadata for submit, approve, reject, cancel, and system auto-cancel flows
- Attendance records support auditable corrections without guessing missing clock-out times
- Shared HR exceptions/contracts exist in `@amdox/types`
- A dedicated HR harness can seed employees, departments, leave types/balances/requests, attendances, outbox events, and notifications
- Prisma schema is pushed and regenerated before plan 02 or 03 work begins
  </must_haves>

5. In `packages/db/prisma/schema.prisma`, update `Attendance`:

## Threat Model

<threat_model>

- **T-05-01: Lifecycle ambiguity** - Without a `PRE_START` state and explicit workflow metadata, roster queries and lifecycle transitions can silently misclassify employees and leave requests.
- **T-05-02: Schema/client drift** - If the live database is not pushed after schema edits, TypeScript types may appear correct while runtime queries fail against stale tables and columns.
- **T-05-03: Harness blind spots** - Without an HR-specific harness, later tests will miss tenant-scoped hierarchy, leave-balance, and attendance-correction edge cases.
  </threat_model>
