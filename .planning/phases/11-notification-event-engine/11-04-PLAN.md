# Plan 11-04: Cross-Module Verification

## Objective

Validate the full Phase 11 engine against the completed phases that already emit events and close the loop with recorded verification evidence.

## Must-Haves

- Completed-phase events flow through the notification engine end to end.
- Preference suppression, template overrides, and webhook broadcast behavior are tested in integration.
- SMS missing-provider behavior is durable and explicit.
- Final build and test evidence is captured in the validation doc.

## Tasks

<task id="11-04-01" status="planned">

### Verify completed-phase events through the engine

Add engine-focused integration coverage for these existing event types:

- `invoice.match_failed`
- `hr.leave.rejected`
- `payroll.run.completed`
- `payroll.run.failed`
- `supply-chain.reorder.skipped`
- `bi.report.ready`
- `project.budget.overrun`

Each test should prove the event can be claimed, resolved, and delivered through the appropriate channels without rewriting upstream producers.

</task>

<task id="11-04-02" status="planned">

### Verify channel behavior, preference suppression, and template fallback

Add integration coverage for:

- in-app delivery
- email delivery
- webhook delivery
- preference-based suppression
- tenant template override versus platform fallback
- missing SMS-provider behavior

These tests should confirm the user’s locked Phase 11 decisions are reflected in runtime behavior.

</task>

<task id="11-04-03" status="planned">

### Run full verification and record evidence

Run the full build and test suite required for the phase:

- `pnpm --filter @amdox/db db:push`
- `pnpm --filter @amdox/db generate`
- `pnpm --filter @amdox/types build`
- `pnpm --filter @amdox/api build`
- `pnpm --filter @amdox/api run test:unit:raw`
- `pnpm --filter @amdox/api run test:integration:raw`

Update `11-VALIDATION.md` with the final evidence and any residual risks before Phase 11 moves to execution-complete verification.

</task>

## Threat Model

- Integration tests must confirm channel delivery does not double-send legacy in-app notifications.
- Broadcast webhook behavior must only target active, tenant-owned endpoints subscribed to the event type.
- Final validation must surface any residual dependency on external provider configuration rather than hiding it.

## Verification

- Engine integration tests prove end-to-end compatibility with completed-phase producers.
- API integration tests and engine tests remain green together.
- Validation doc records the exact evidence and commands used to close the phase.

## Success Criteria

- Wave 4 proves that Phase 11 works as a cross-cutting engine for the phases already shipped and leaves a clean evidence trail for downstream work.
