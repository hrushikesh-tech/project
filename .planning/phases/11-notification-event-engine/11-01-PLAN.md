# Plan 11-01: Notification Foundations

## Objective

Create the shared contracts, retry bookkeeping, schedule constants, and Wave 0 harness required to implement the Phase 11 delivery engine without reworking upstream event producers.

## Must-Haves

- Shared notification contracts and catalog primitives include current completed-phase event types.
- Prisma supports bounded retry and durable terminal-outcome visibility for outbox processing.
- A reusable notification test harness exists before deeper engine work starts.
- Blocking schema and build commands pass before Wave 2 and Wave 3 begin.

## Tasks

<task id="11-01-01" status="planned">

### Create shared notification contracts and seeded event catalog

Add notification-specific shared types under `packages/types` for:

- supported channels
- catalog entry shape
- template variable contracts
- recipient-resolution contracts
- delivery result summaries

Seed the catalog contract surface with the completed-phase event types already emitted in code:

- `invoice.match_failed`
- `hr.leave.rejected`
- `payroll.run.completed`
- `payroll.run.failed`
- `supply-chain.reorder.skipped`
- `bi.report.ready`
- `project.budget.overrun`

Also include structure for the broader 20+ future event families so later phases can plug in without another contract redesign.

</task>

<task id="11-01-02" status="planned">

### Evolve Prisma outbox bookkeeping for retries and terminal outcomes

Update the Prisma schema so `OutboxEvent` can durably represent:

- next eligible retry time
- bounded retry attempts
- last error or failure reason
- final terminal outcome such as delivered, failed, or skipped

Keep the design minimal and compatible with existing producers. The model should remain the single durable source used by the poller and delivery worker.

</task>

<task id="11-01-03" status="planned">

### Create notification test harness and schedule constant

Add a reusable notification test store helper that can stand up:

- outbox rows
- notifications
- preferences
- webhook configs
- template overrides

Also add a centralized 5-second notification polling schedule constant in the existing schedule utility so the implementation and tests share one cadence definition.

</task>

<task id="11-01-04" status="planned">

### Run blocking schema and build synchronization

After the schema and shared contracts land, run the blocking sync commands:

- `pnpm --filter @amdox/db db:push`
- `pnpm --filter @amdox/db generate`
- `pnpm --filter @amdox/types build`
- `pnpm --filter @amdox/api build`

Do not begin deeper module or engine work until these commands pass.

</task>

## Threat Model

- Retry metadata must not allow cross-tenant event leakage or ambiguous state transitions.
- Shared catalog contracts must not permit arbitrary untyped payload handling for security-sensitive channels.
- Schedule constants and harness utilities must stay deterministic so queue processing tests remain trustworthy.

## Verification

- Prisma schema parses and generates cleanly.
- Shared types compile and are importable from downstream packages.
- Notification harness can construct tenant-safe test data.
- Blocking build commands pass after Wave 1 changes.

## Success Criteria

- Wave 1 leaves the repo with stable notification contracts, inspectable retry state, a reusable test harness, and no schema or build blockers for later waves.
